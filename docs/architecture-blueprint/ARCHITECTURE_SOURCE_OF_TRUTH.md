## 4. Event contracts

Transport: `audit_events` (immutable, DB trigger) as the domain-event log, and `background_jobs` (enqueued in the same transaction) for asynchronous work. No broker. Proposed: ADR-012 adds `event_version`, `correlation_id` and consumer cursors.

| Event (`action` / job type) | Producer | Consumer |
|---|---|---|
| `mission.created · updated · authorized` | mission_service | readiness, polling consumers |
| `finding.created · disposition_added · closed` | finding_service | evidence intelligence, M7 |
| `work_order.created · updated · assigned · transitioned` | work_order_service | TAT, release readiness |
| `task.created · updated · completed` | work_order_service | inspection gate |
| `component/battery .installed · .removed` | installation_service | configuration as-of view |
| `inspection.completed · rejected · marked_not_required · reopened` | inspection_service | release readiness |
| `M7 signal lifecycle transitions` | proactive_intelligence_service | audit |
| `acquisition.ingest (job)` | listeners, HTTP async, webhooks | worker → acquisition_service.ingest |
| `acquisition.poll (job)` | scheduler | worker → OEM poller |
| `retention.sweep · billing.dunning (jobs)` | scheduler | worker |

Canonical telemetry contract: `NormalizedTelemetryEvent` (app/schemas/telemetry.py) — source_system, source_event_id, source_asset_id, event_type, event_timestamp, flight?, battery?, readings[] (sensor_code, sensor_type, measurement_type, finite value, unit, component_id, data_quality), raw_metadata.

## 6. Trust boundaries

- Public → authenticated: JWT (exp + sub required, DB re-check per request), HMAC webhooks, MAVLink-2 signing.
- Authenticated → tenant: organization_id from caller or DataSource row only; foreign ids → 404.
- Tenant → internal: RBAC permission + router-level entitlement; ownership checks on cross-references. **Gap F3:** async ingestion paths skip entitlement.
- Internal → data: parameterised SQL; immutable audit; evidence checksums; secrets via KOTA_SECRET_<ref>.
- AI boundary: LISA tools authorised per call; no organisation argument; deterministic airworthiness guard. **Gap F5:** no separate DB role; tool calls not persisted to audit.
- Admin control plane: PLATFORM_ADMIN with platform:manage; four-eyes approvals for expansive tenant changes.

## 9. Known gaps

- **F1 (High) Neo4j decision conflict.** ADR-003 (Accepted) and the M14 report describe Neo4j as a derived graph fed by an outbox. The code uses PostgreSQL only (knowledge_graph.py, digital_twin_service.py); neo4j_* settings are unused, yet docker-compose still starts Neo4j. The gap matrix records the change but ADR-003 was never superseded. → Write ADR-011 superseding ADR-003; remove Neo4j from local compose or mark optional.
- **F2 (High) No transactional outbox / event bus.** Domain events are AuditEvent rows consumed by polling; asynchronous work uses the background_jobs table enqueued inside the request transaction. This is outbox-equivalent for jobs, but there is no versioned event contract, no consumer offsets and no replay tool. → Formalise audit + jobs as the event backbone (event_version, correlation_id), not a broker.
- **F3 (High) Async ingestion ignores entitlement changes.** Router-level require_feature guards the HTTP surfaces, but job handlers, listeners and OEM polls do not re-resolve entitlements. A tenant whose subscription is cancelled keeps ingesting through an ACTIVE data source until it is paused. → Check flight_telemetry entitlement in acquisition_service.ingest and the poll scheduler.
- **F4 (High) Store-and-forward is not durable.** The edge gateway buffers in a bounded in-memory deque (oldest dropped on overflow, lost on power cycle), and MAVLink events are stamped with arrival time, so post-flight synchronised data loses its true measurement time. → Disk-backed queue on the gateway; carry SYSTEM_TIME / GPS epoch and a gateway sequence number.
- **F5 (Medium) AI write boundary is convention, not structure.** ADR-004/005 require a separate DB role for the AI module without write grants. LISA runs in the API's own session; one tool (run_assessment) writes. ADR-001's import-linting is not configured. Tool invocations are returned to the caller but not persisted to the audit log. → Classify tools read / draft / write; persist every tool call as an AuditEvent; add import-linter contracts.
- **F6 (Medium) Reads that write (signal sync on GET).** M7 sync_and_get_signals and HUMS get_asset_health_intelligence persist records during GET requests. Correct today (idempotent keys, advisory locks) but couples read latency to write contention and makes the signal authority depend on who reads first. → Move sync to worker jobs triggered by telemetry / MRO events; keep GET read-only.
- **F7 (High) Signal vocabulary drift (with a live defect).** /proactive (legacy computed alerts + daily brief) coexists with M7 /intelligence/signals. 'M14' names both the commercialisation milestone and the cross-asset intelligence service; signal_type is a free string(64). Concrete defect: M7's overdue-maintenance rule filters work orders on AWAITING_PARTS / SCHEDULED, which are not WorkOrderStatus values, so PLANNED, ASSIGNED, ON_HOLD and INSPECTION work orders never raise overdue signals (proactive_intelligence_service.py:74). → Fix the status filter to WorkOrderStatus constants; retire or fold /proactive into M7; registry for signal types.
- **F8 (Medium) Compliance lineage and rule versioning.** Applicability evaluations keep configuration_snapshot and reasoning_trace (good), but rules have no version and the ADR-005 human-decision / final-status / previous-assessment lineage is not in the schema. → Add rule_version + effective dating; implement ADR-005 decision rows or amend the ADR.
- **F9 (Medium) CI runtime drift.** CI and the Dockerfile pin Python 3.11, but tests/integration/test_observability.py uses 3.12-only f-string syntax and fails collection on 3.11. CI also does not run the frontend vitest suite. In this audit's independent run one listener test failed deterministically (a start-up race in the test). → Pin Python 3.12 everywhere (or fix the test); add vitest to CI.
- **F10 (Low) Documentation drift.** Several documents describe targets as if built (Redis cluster, TimescaleDB, ai_tool_audit_log, WORM storage, RPO < 15 min). Most now carry status banners; FINAL_RELEASE_READINESS still lists G1 as open while the gap matrix lists it closed. → Treat this blueprint's status register as the index; banner or archive superseded documents.

## 10. Glossary

- **AD** — Airworthiness Directive — mandatory regulatory requirement issued against a type certificate.
- **ADR** — Architecture Decision Record — documented decision with context, alternatives and consequences.
- **AOG** — Aircraft on Ground — asset unable to operate pending maintenance or parts.
- **Applicability** — Deterministic evaluation of whether a requirement applies to an asset configuration (TRUE / FALSE / UNKNOWN).
- **Data source** — Tenant-bound configuration of one telemetry feed (connector type, mapping, health).
- **Entitlement** — Commercial right to a feature, resolved from suite → plan → subscription → overrides → limits.
- **eVTOL / AAM** — Electric vertical take-off and landing / advanced air mobility.
- **Exceedance** — A reading or feature beyond a configured warning / critical limit or statistical threshold.
- **HUMS** — Health and Usage Monitoring System — health, usage, diagnostics, prognostics.
- **Kleene logic** — Three-valued logic where UNKNOWN is never silently treated as FALSE.
- **LISA** — Kota's grounded assistant — answers only from authorised tool results.
- **M4.2** — Fleet intelligence control center — presentation and decision summary over per-asset intelligence.
- **M7** — Proactive intelligence — canonical owner of actionable signals and their lifecycle.
- **M14-ext** — Cross-asset intelligence extension (H8.1) — descriptive fleet distributions. Not the M14 commercial milestone.
- **MAVLink** — Lightweight message protocol for drones and autopilots; a framing format, not a cloud endpoint.
- **MRO** — Maintenance, repair and overhaul.
- **Outbox** — Pattern where events are written in the same transaction as state, then published asynchronously.
- **RBAC** — Role-based access control (permissions per role, checked server-side).
- **RII** — Required Inspection Item — independent inspection by a second qualified person.
- **RUL** — Remaining Useful Life — estimate, never a certified life limit.
- **Signal** — Persisted, actionable M7 record with severity, explanation trace and lifecycle.
- **SKIP LOCKED** — PostgreSQL row-locking mode letting parallel workers claim different jobs.
- **Suite** — Product family: Aircraft, Drone/UAV, Helicopter, eVTOL/AAM.
- **Tenant** — A customer organisation; every row carries organization_id.
