## 2. Session & Error Handling Continuity

1. **Token Refresh Continuity:** Single-flight refresh token mutex in `apiClient.ts` prevents refresh collisions during concurrent multi-panel dashboard loads. When a token is refreshed, `aerocomply_token_refreshed` custom event notifies all open tabs.
2. **Expired Session Termination:** 401 response triggers token purge, dispatches `aerocomply_auth_logout`, and redirects cleanly to `/login` without looping or leaking partially rendered UI.
3. **Optimistic Mutation Safety:** Work order creation, mission authorization, and predictive MRO candidate conversions do not use blind retries; idempotency keys and server-side state transitions prevent duplicate creation.
4. **Empty State & Loading Standards:** All data-table components render standardized loading skeletons during fetches, informative empty-state cards when collections are empty, and explicit error banners on API failures rather than infinite loading spinners.
